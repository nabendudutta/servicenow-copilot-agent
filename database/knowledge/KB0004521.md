# KB0004521: Resolving Terraform State Lock Errors in CI/CD Pipelines

## Content

### Problem
Terraform pipelines fail with the error:
```
Error: Error acquiring the state lock
Error message: ConditionalCheckFailedException: The conditional request failed
Lock Info:
  ID:        xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
  Path:      s3://my-tf-state/project/terraform.tfstate
  Operation: OperationTypePlan
  Who:       runner@github-actions
  Created:   2024-04-10 08:23:11.123456789 +0000 UTC
```

### Root Cause
Terraform uses DynamoDB (AWS) or a storage lock mechanism (Azure/GCP) to prevent concurrent state modifications. A lock persists if a previous Terraform process was killed mid-run (e.g., a GitHub Actions job was cancelled or timed out).

### Resolution Steps

**Step 1 — Verify the lock is stale**
Check if any pipeline is currently running. If not, the lock is stale.

**Step 2 — Force-unlock (AWS)**
```bash
# Get the Lock ID from the error message
terraform force-unlock <LOCK_ID>
```

**Step 3 — Force-unlock via DynamoDB (if CLI unavailable)**
```bash
aws dynamodb delete-item \
  --table-name terraform-state-locks \
  --key '{"LockID": {"S": "s3://my-tf-state/project/terraform.tfstate"}}' \
  --region us-east-1
```

**Step 4 — Re-run the pipeline**
After unlocking, re-trigger the failed GitHub Actions workflow.

### Prevention
- Set `timeout-minutes` on all Terraform jobs in GitHub Actions to auto-cancel stale runs
- Enable DynamoDB TTL on lock items (30-minute TTL recommended)
- Use `terraform plan -lock-timeout=60s` to auto-retry lock acquisition

### GitHub Actions Example (with lock timeout)
```yaml
- name: Terraform Plan
  run: terraform plan -lock-timeout=300s -out=tfplan
  timeout-minutes: 15
```
